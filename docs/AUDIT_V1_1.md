# RECAP — результат первого технического аудита (v1.1, 19.11.2026)

## Архитектура

Три контура сохранены без изменений: `/frontend` (React/Vite/Telegram Mini Apps), `/backend` (Cloudflare Workers + D1), `/scanner` (отдельный FastAPI/Telethon-сервис). Telegram Takeout не добавлялся. Медиафайлы не скачиваются. Обязательные подписки и платные блокировки не добавлялись.

## Исправлено в этом архиве

1. `frontend/src/App.tsx`: **Live больше не подставляет демо-цифры** при отсутствии реальных результатов. Нет данных — показывается объяснение, а не вымышленный Wrapped.
2. Frontend API и Worker: статус сканирования нормализован из `snake_case` D1 в `camelCase` TypeScript; состояние прогресса теперь соответствует контракту `ScanProgressPayload`.
3. `frontend/src/App.tsx` + `frontend/src/api/client.ts` + `backend/src/index.ts`: добавлено возобновление прежнего `job_id` после отмены/partial через новую QR/телефонную авторизацию, а не запуск нового задания с потерей чекпоинта. Возобновление работает **пока чекпоинт сохранился на диске сканера**.
4. `scanner/app/analyzer.py`: сохранены прежние правила пагинации, границы года, проверка владельца чекпоинта; живые имена чатов заменены нейтральными метками. При загрузке старых чекпоинтов названия также очищаются.
5. При FloodWait сканирование теперь можно быстрее отменить, не дожидаясь окончания всей паузы (сохранив тестовый таймер для unit-тестов).
6. `scanner/app/server.py`: сопоставление заданий с владельцами и сигнал отмены всех заданий пользователя при отзыве аккаунта.
7. `backend/src/index.ts`: callback проверяется по `job_id`, пользователю, году и часовому поясу; отменённые/завершённые задания не должны «воскресать» от запоздавших событий.
8. Backend: ошибки запуска scanner больше не оставляют скрыто активное D1-задание; `DELETE /api/data`, `/delete` в боте не заявляют об успешном отзыве сессии при недоступном scanner. Отмена также не заявляется успешной без ответа scanner.
9. `backend/src/crypto.ts`: проверка будущего `auth_date`, дублированных полей и некорректных Telegram user id.
10. `frontend/src/App.tsx`: исправлен бесконечный демонстрационный FloodWait (раньше застревал на 40 чатах); кнопка отмены прекращает демо-таймер. Demo в продакшене выключен по умолчанию, включение — через явное `VITE_ENABLE_DEMO=true`.
11. `frontend/src/data/demoData.ts`: суммы демо-сообщений согласованы по дням недели/часам/месяцам; за декабрь 2026 не показываются сообщения в ноябре.
12. `.github/workflows/deploy.yml`: перед деплоем добавлен backend typecheck; frontend build был и остаётся обязательным шагом.
13. `scanner/app/server.py`: scanner проверяет HTTP-статус callback в Worker, повторяет временно неудачные доставки и не считает отклонённый callback успешным.
14. `tests/test_analyzer.py`: два дополнительных теста на изоляцию владельца чекпоинта и защиту названий чатов.

## Что остаётся для безопасного публичного запуска

- Долгие сканирования реализованы через `asyncio.create_task` внутри FastAPI. Рестарт контейнера прерывает задачи; требуется надёжная внешняя очередь/worker, мониторинг и контролируемое восстановление.
- Авторизации и зашифрованные Session строки находятся в памяти одного процесса, поэтому нельзя масштабировать сервис на несколько реплик без отдельной архитектуры хранения состояния.
- Чекпоинты лежат на локальном диске (`CHECKPOINT_DIR`, по умолчанию `/tmp/recap_checkpoints`): для переживания рестартов требуется защищённый постоянный диск или отдельное хранилище. Не сохраняйте сырые MTProto Session Strings.
- Нужны живые тесты QR, 2FA, revoke через `auth.logOut`, отмены во время FloodWait, больших чатов и разных типов Telegram-сообщений.
- Требуются rate limiting, подтверждение TLS/доступа к scanner, политика хранения/срок жизни сессий, внятная privacy-политика, тесты Backend маршрутов (подмена user id, фальшивые callback и отмена).
- Завершение MTProto-сессии через Telethon может закончиться ошибкой сети; реализация делает попытку, но **невозможно гарантировать отзыв**. Пользователь должен проверить Telegram → Настройки → Устройства.
- Перед публичным запуском настроить реальные секреты только через защищённые настройки Cloudflare и сканера, без передачи в чат или файлов репозитория.
